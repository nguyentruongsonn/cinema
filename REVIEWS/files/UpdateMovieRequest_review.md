### Issue #1

Severity:
Critical

Category:
Authorization

Location:
app/Http/Requests/UpdateMovieRequest.php:19-23

Problem

The request authorizes every caller and relies on an external middleware comment:

```php
public function authorize(): bool
{
    // Authorization is handled by middleware (admin role required)
    return true;
}
```

Why this matters

Movie updates are administrative operations. If the request is reused on another route, middleware is removed, route groups are misconfigured, or a test route is exposed, any authenticated or unauthenticated caller may pass request authorization. Authorization should not be expressed only as a comment.

How to fix

Enforce explicit authorization through a policy or permission check.

Example

```php
public function authorize(): bool
{
    return $this->user()?->can('update', $this->route('movie')) === true;
}
```

If route model binding is not used, resolve the movie safely and check an admin permission.

### Issue #2

Severity:
High

Category:
Validation / Database Correctness

Location:
app/Http/Requests/UpdateMovieRequest.php:32-40

Problem

The slug uniqueness ignore value is taken from `route('id')`:

```php
$movieId = $this->route('id');

Rule::unique('movies', 'slug')->ignore($movieId),
```

Why this matters

This assumes the route parameter is named `id`. If the route uses `{movie}`, route model binding, or another parameter name, `$movieId` may be `null` or an object. That can cause false unique validation failures or incorrect ignore behavior. Slug uniqueness is a public URL integrity concern.

How to fix

Use route model binding consistently or normalize the route parameter explicitly.

Example

```php
$movie = $this->route('movie');

$movieId = $movie instanceof \App\Models\Movie ? $movie->getKey() : $movie;

Rule::unique('movies', 'slug')->ignore($movieId);
```

Also ensure the database has a unique index on `movies.slug`.

### Issue #3

Severity:
High

Category:
Security / XSS

Location:
app/Http/Requests/UpdateMovieRequest.php:43,51-52

Problem

Large display fields are only validated as strings:

```php
'description' => ['nullable', 'string'],
'director' => ['nullable', 'string', 'max:255'],
'cast' => ['nullable', 'string', 'max:255'],
```

Why this matters

These fields are likely rendered in frontend/movie detail pages. The request does not restrict HTML, scripts, dangerous markup, or control characters. If the frontend renders this content unsafely, this becomes stored XSS.

How to fix

Define whether HTML is allowed. If not, strip tags or use custom validation to reject markup. If HTML is allowed, sanitize it server-side with an allowlist.

Example

```php
'description' => ['nullable', 'string', 'max:10000'],
'director' => ['nullable', 'string', 'max:255', 'not_regex:/<[^>]*>/'],
'cast' => ['nullable', 'string', 'max:1000', 'not_regex:/<[^>]*>/'],
```

Sanitization should happen before persistence.

### Issue #4

Severity:
High

Category:
Security / URL Validation

Location:
app/Http/Requests/UpdateMovieRequest.php:44-45

Problem

Poster and trailer URLs are validated only as strings:

```php
'poster_url' => ['nullable', 'string', 'max:255'],
'trailer_url' => ['nullable', 'string', 'max:255'],
```

Why this matters

These values may be rendered as links, image sources, embeds, or passed to clients. A plain string can contain unsupported schemes, JavaScript/data URLs, internal URLs, malformed paths, or payloads that trigger frontend issues. This also creates SSRF risk if backend code later fetches these URLs.

How to fix

Validate URL format and allowed schemes/domains.

Example

```php
'poster_url' => ['nullable', 'url', 'max:2048', 'starts_with:https://'],
'trailer_url' => ['nullable', 'url', 'max:2048', 'starts_with:https://'],
```

For uploads, prefer storing controlled file paths generated by the backend rather than arbitrary client-provided URLs.

### Issue #5

Severity:
High

Category:
Validation / Business Logic

Location:
app/Http/Requests/UpdateMovieRequest.php:54-57

Problem

Administrative status fields are directly accepted from the request:

```php
'status' => ['sometimes', 'boolean'],
'is_hidden' => ['sometimes', 'boolean'],
'manual_override_status' => ['nullable', 'integer', 'min:0'],
'is_hot' => ['sometimes', 'boolean'],
```

Why this matters

These fields control public visibility and scheduling behavior. The request allows callers to mutate them without field-level authorization or clear domain constraints. `manual_override_status` accepts any integer greater than or equal to zero, so invalid state values can be persisted if the service trusts validated data.

How to fix

Use explicit enum/range validation and enforce permission checks for administrative state changes.

Example

```php
'manual_override_status' => ['nullable', Rule::in([0, 1, 2])],
```

Consider splitting content updates from publication/status updates into separate requests/endpoints with separate policies.

### Issue #6

Severity:
Medium

Category:
Money Correctness

Location:
app/Http/Requests/UpdateMovieRequest.php:50

Problem

`surcharge` is validated as generic numeric money:

```php
'surcharge' => ['nullable', 'numeric', 'min:0'],
```

Why this matters

Generic numeric validation allows arbitrary precision and floats. Movie surcharge affects pricing and revenue. Unbounded precision can cause rounding mismatches, gateway reconciliation issues, and database precision errors.

How to fix

Use integer minor units or strict decimal precision with a maximum.

Example

```php
'surcharge' => ['nullable', 'decimal:0,2', 'min:0', 'max:999999.99'],
```

Prefer storing money as integer cents/VND minor units where appropriate.

### Issue #7

Severity:
Medium

Category:
Validation / Business Logic

Location:
app/Http/Requests/UpdateMovieRequest.php:46-49

Problem

Date and duration fields are under-constrained:

```php
'duration' => ['sometimes', 'integer', 'min:1'],
'release_date' => ['sometimes', 'date'],
'end_date' => ['nullable', 'date', 'after_or_equal:release_date'],
'age_rating' => ['nullable', 'string', 'max:50'],
```

Why this matters

The request permits unrealistic durations, arbitrary date ranges, and free-form age ratings. `end_date` also only compares against submitted `release_date`; partial updates may not validate against the existing movie release date if only `end_date` is changed.

How to fix

Add domain bounds and enum validation. Validate partial-update date consistency against the persisted movie when one side is omitted.

Example

```php
'duration' => ['sometimes', 'integer', 'min:1', 'max:600'],
'age_rating' => ['nullable', Rule::in(['P', 'K', 'T13', 'T16', 'T18'])],
```

Use an after-validator or custom rule for existing `release_date`/`end_date` consistency.

### Issue #8

Severity:
Medium

Category:
Validation / Performance

Location:
app/Http/Requests/UpdateMovieRequest.php:53,58-59

Problem

Array fields are unbounded:

```php
'backdrops' => ['nullable', 'array'],
'category_ids' => ['nullable', 'array'],
'category_ids.*' => ['integer', 'exists:categories,id'],
```

Why this matters

A caller can submit very large arrays, causing excessive validation queries, memory usage, and downstream attach/sync work. `category_ids` also lacks `distinct`, allowing duplicate IDs in the payload.

How to fix

Add maximum sizes and distinct validation.

Example

```php
'backdrops' => ['nullable', 'array', 'max:20'],
'backdrops.*' => ['string', 'url', 'max:2048'],
'category_ids' => ['nullable', 'array', 'max:10'],
'category_ids.*' => ['integer', 'distinct', 'exists:categories,id'],
```

### Issue #10

Severity:
Medium

Category:
Validation / API Correctness

Location:
app/Http/Requests/UpdateMovieRequest.php:34-60

Problem

The request allows an empty update payload because every field is optional or nullable.

```php
return [
    'title' => ['sometimes', 'string', 'max:255'],
    // ...
    'category_ids' => ['nullable', 'array'],
];
```

Why this matters

Empty update requests can produce misleading successful responses, unnecessary writes, audit noise, and confusing client behavior.

How to fix

Require at least one updatable field.

Example

```php
public function withValidator($validator): void
{
    $validator->after(function ($validator) {
        if (empty($this->validated())) {
            $validator->errors()->add('payload', 'At least one field must be provided.');
        }
    });
}
```

----------------------------------------------------

Final Assessment

`UpdateMovieRequest` is better structured than several other request classes, but it is not production-ready for administrative movie mutation. The biggest problems are blanket authorization, fragile route parameter handling for slug uniqueness, arbitrary URL/string fields, under-constrained publication status fields, weak money validation, and unbounded arrays. Before approval, the request should enforce policy-based authorization, strict domain rules, bounded payloads, safe URL/content validation, and update consistency for partial date changes.
